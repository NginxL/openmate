# OpenMate 路线图

OpenMate 是一组 Persona 扩展，把聊天软件接进 [Persona](https://github.com/nwverse/persona)。

- 聊天软件里的消息进入 Persona 的收件箱和知识库。
- Persona 的助手和 Agent 能以你本人的身份，在这些聊天软件里查消息、回消息，处理 `/agent` 请求。

本仓库同时是一个 Persona 扩展市场：在 Persona 里添加 `github:NginxL/openmate` 即可安装。

## 原则

- **从零实现：** 只依据 Persona（MIT）公开的扩展与连接器协议编写，不含其他飞书桥接项目的代码或文字。
- **不分发第三方组件：** 非官方协议库（例如 LarkAgentX）不打包、不再分发，由使用者自行安装。
- **发送要确认：** 每次以你本人身份主动发出的消息，都要先在手机上确认全文和目标。`/agent` 的回复例外，它是你本人发起的请求；这些回复每一条都记进 Persona 的“以你身份发出的消息”记录（连接器声明 `sends_as_user`，发出后调用 `sent.record`）。
- **平台无关的逻辑共用：** 收件箱、会话页、知识库、`/agent` 都写在 `core` 里。每个平台只需实现一个后端（`core/openmate_core/backend.py`）。

## 二期：在 Persona 里发布和安装

- GitHub Actions 跑测试，检查发布包和市场索引是最新的。完成。
- 在 Persona 管理端添加市场、安装、验证，然后替换原来的飞书桥接。完成。

## 三期

- **@我 触发：** 别人在你标记过的群里 @你 时，由 AI 起草回复。
  - 每个群可以单独选“先确认”或“直接发”，默认先确认。
  - 用 Persona 的访客对话机制，AI 只能使用少量受限工具。
- **文档评论：** 文档评论里 @你 提问时由 AI 回复；在 wiki 评论里用 `/agent` 总结文档。需要先验证可行的接口。

## 个人控制台

目标：打开 Persona 就能看到“今天”：需要我处理的事、今天的待办和日程、各个聊天软件里 @我 的消息、正在跑的 Agent，每一块都有数字，点进去就是详情。

| 功能 | 做法 | 状态 |
| --- | --- | --- |
| 飞书今天：@我、没回的私聊、今天活跃的群，点开看最近的消息；侧栏徽标显示要处理几件 | `openmate-feishu` 的侧栏页面“飞书”（0.8.0 起总览上并进“今天”卡片） | 完成（0.2.0） |

| 日记、订阅、账单、财务 | 各自一个扩展；账单和订阅从邮件里提取 | 之后 |

需要 Persona 本身先支持的，已经提给 Persona：

- 健康数据和手机上的日历、提醒事项、位置开放给扩展只读。
- 足迹：手机持续记录到访的地点。
- 首页和侧栏：可以把扩展的页面设为首页，侧栏可以分组。
- 隐藏不用的内置助手。
- Persona 自带的“总览”页卡片可以拖动排序、隐藏，并选整行或半行（交给 Persona 实现，接 #9351 的页面排列）。
- 扩展页面的多列布局：卡片两两并排、整行卡片、卡片标题旁的图标和链接（nwverse/persona#9226，UI 版本 8，已合并；“今天”页 0.3.8 起支持，hub 升级后生效）。
- hub 转发到 manager 的请求复用连接，减少每次刷新的等待（nwverse/persona#9220，已合并，hub 升级后生效）。
